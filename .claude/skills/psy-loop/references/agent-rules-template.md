## Ironclad rules (psy-loop dispatch, tiered-review policy)

Orchestrator: copy this file to the session scratchpad as `agent-rules-<project-slug>-<YYYY-MM-DD>.md` and replace `<SESSION_URL>` and `<MODEL_NAME>` (the dispatched model's display name) before the first dispatch; `grep -n 'SESSION_URL\|MODEL_NAME'` on the copy must print nothing. `<BRANCH>` and `<BASE>` are per-ticket placeholders that stay in this file; the brief supplies their values. Every brief cites the copy by its absolute path; every rule applies to every agent.

You are a dispatched implementation agent in an ISOLATED git worktree. The orchestrator merges nothing on your behalf; you never merge, never mark the Linear ticket Done, never push to main.

1. **Isolation first.** Sub-agents you spawn for ANY purpose are `subagent_type: "general-purpose"` with `model: "opus"`, never `fork`. Run `pwd` and `git rev-parse --show-toplevel`; both must be under `.claude/worktrees/`. Then branch off the CURRENT base, not the inherited HEAD: `git fetch origin && git checkout -b <BRANCH> <BASE>` (BASE given in the brief). Every Edit/Write must land under that worktree path; verify with `git status` before your first commit.
2. **Verify the premise before building.** Read the actual code the ticket cites; if the ticket's claim is wrong or already fixed on the base, STOP and report instead of building.
3. **No speculative design.** If the ticket leaves a WHAT undecided (copy, thresholds, taxonomy, UX pattern), stop and report the fork; do not pick.
4. **Gates before any push** (a failing gate blocks the push; report it, do not push past it). Run every suite in the FOREGROUND with an explicit timeout under the Bash tool's 600 s ceiling; a backgrounded suite you wait on gets you killed by the watchdog.
   - `cd backend && go build ./...`; scoped `go test ./<pkg>/... -count=1`; scoped lint `go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.12.2 run --config=.golangci.yml ./<touched-pkgs>/...`; `go generate ./...` must produce no diff. The FULL Go suite does not fit the ceiling: for an interface or contract change, run the scoped suites of every package that imports the changed package, sweep for hand-rolled stubs of the interface in other packages' tests (`grep -rn "stub<Name>\|var _ contracts.<Interface>" backend/`) and run those packages too, state in the PR body that the full suite runs in CI, and never check a box for a run you did not do.
   - Frontend: `bun run typecheck`, `bun run lint`, `bun run test:run <touched scopes>`. If any backend API shape changed: `bun run api:types` in the SAME PR.
   - CLI: `cd cli && bun x tsc --noEmit && bun test`.
   - Known-flake carve-out (cite ticket + an isolated pass, then proceed): `TestRepeatedRestartsStillMakeProgress`, `TestTriggerGlobalRematch*` (PSY-1958), ShowForm unmount-timer (PSY-1980). Anything else failing = STOP and report.
5. **Manual repro is mandatory** before the PR: isolated stack via `bash scripts/dispatch/stack-up.sh "$(git rev-parse --show-toplevel)" --mode=isolated` (backend on the printed port; DB creds dispatchuser/dispatchpassword/dispatchdb; e2e users `e2e-user-1@test.local` etc. with password `e2e-test-password-123`; admin `e2e-admin@test.local`; `POST /auth/login` returns a cookie session; `phk_` tokens are admin-only). curl the changed behaviour end-to-end and record the matrix in the PR body. Tear the stack down after (`stack-down.sh`). For a user-visible UI change: light+dark screenshots uploaded to a `gh release` (psy-solo pattern) and embedded in the PR; if the upload is refused, leave the PNG paths in your report.
6. **Review gauntlet, in order, each as its OWN commit:** `/simplify` fixes (`/code-review` is user-invocable only and will error for you; do not try it, and never imply it ran); then adversarial review per the TIER stated in the brief, with fixes in `PSY-N: adversarial-review fixes` commits; then `/psy-self-review` on the drafted PR body (every `[x]` must be backed by a run you did). Fresh panels = spawn reviewer sub-agents as `subagent_type: "general-purpose"` with `model: "opus"` (never `fork`: a fork inherits your whole prompt and can ship on its own, PSY-1088), giving each ONLY the diff + a one-line intent (never your reasoning); reviewers are read-only auditors. If you have no Agent tool, or the spawn fails and one retry fails too, tell the orchestrator first (an inline pass runs long and silent and trips the stall watchdog), then run the lenses inline per `adversarial-review` Step 1 and write "run INLINE: no independent context reviewed this diff" in the PR body's attribution line. BLOCK verdicts must be fixed or refuted with a concrete technical counter-argument; cap 3 rounds. Attribution in the PR body names ONLY lenses that actually reported; a stalled lens is never "corroboration"; never write a verdict before the result exists.
7. **Rebase, re-gate, push.** `git fetch origin && git rebase <BASE>`, re-run the touched-package suites, then `git push -u origin <BRANCH>`. Migrations: version must exceed main's max at push time.
8. **Pass-marker, then PR.** Only on a passing verdict (CLEAN, or CONCERNS with the MEDIUMs fixed or disclosed; never on an unresolved BLOCK), after the rebase so the marker records the pushed HEAD: `mkdir -p ~/.claude/adversarial-review; repo="$(git rev-parse --show-toplevel)"; branch="$(git rev-parse --abbrev-ref HEAD)"; key="$(printf '%s' "${repo}__${branch}" | tr '/ ' '__')"; printf '{"repo":"%s","branch":"%s","head":"%s","verdict":"%s","ts":"%s"}\n' "$repo" "$branch" "$(git rev-parse HEAD)" "<the actual verdict: CLEAN or CONCERNS>" "$(date -u +%FT%TZ)" > ~/.claude/adversarial-review/"$key".pass`. Then open the PR with `gh pr create` from the worktree root (so the hook's key matches) as its OWN Bash command: the PreToolUse hook gates the whole command it appears in, so anything batched with it never runs.
