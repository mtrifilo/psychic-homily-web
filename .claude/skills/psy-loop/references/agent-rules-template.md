## Ironclad rules (psy-loop dispatch, tiered-review policy)

Copy this file to the session scratchpad as `agent-rules-template.md` and replace `<SESSION_URL>` and `<MODEL_NAME>` before the first dispatch. Every brief cites it; every rule applies to every agent.

You are a dispatched implementation agent in an ISOLATED git worktree. The orchestrator merges nothing on your behalf; you never merge, never mark the Linear ticket Done, never push to main.

1. **Isolation first.** Run `pwd` and `git rev-parse --show-toplevel`; both must be under `.claude/worktrees/`. Then branch off the CURRENT base, not the inherited HEAD: `git fetch origin && git checkout -b <BRANCH> <BASE>` (BASE given in the brief). Every Edit/Write must land under that worktree path; verify with `git status` before your first commit.
2. **Verify the premise before building.** Read the actual code the ticket cites; if the ticket's claim is wrong or already fixed on the base, STOP and report instead of building.
3. **No speculative design.** If the ticket leaves a WHAT undecided (copy, thresholds, taxonomy, UX pattern), stop and report the fork; do not pick.
4. **Gates before any push** (a failing gate blocks the push; report it, do not push past it). Run every suite in the FOREGROUND with an explicit timeout; a backgrounded suite you wait on gets you killed by the watchdog.
   - `cd backend && go build ./...`; scoped `go test ./<pkg>/... -count=1`; for any interface/contract change the FULL `go test ./... -count=1 -timeout 45m -p 1`; scoped lint `go run github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.12.2 run --config=.golangci.yml ./<touched-pkgs>/...`; `go generate ./...` must produce no diff.
   - Frontend: `bun run typecheck`, `bun run lint`, `bun run test:run <touched scopes>`. If any backend API shape changed: `bun run api:types` in the SAME PR.
   - CLI: `cd cli && bun x tsc --noEmit && bun test`.
   - Known-flake carve-out (cite ticket + an isolated pass, then proceed): `TestRepeatedRestartsStillMakeProgress`, `TestTriggerGlobalRematch*` (PSY-1958), ShowForm unmount-timer (PSY-1980). Anything else failing = STOP and report.
5. **Manual repro is mandatory** before the PR: isolated stack via `bash scripts/dispatch/stack-up.sh "$(git rev-parse --show-toplevel)" --mode=isolated` (backend on the printed port; DB creds dispatchuser/dispatchpassword/dispatchdb; e2e users `e2e-user-1@test.local` etc. with password `e2e-test-password-123`; admin `e2e-admin@test.local`; `POST /auth/login` returns a cookie session; `phk_` tokens are admin-only). curl the changed behaviour end-to-end and record the matrix in the PR body. Tear the stack down after (`stack-down.sh`). For a user-visible UI change: light+dark screenshots uploaded to a `gh release` (psy-solo pattern) and embedded in the PR; if the upload is refused, leave the PNG paths in your report.
6. **Review gauntlet, in order, each as its OWN commit:** `/simplify` (or code-review) fixes, then adversarial review per the TIER stated in the brief, with fixes in `PSY-N: adversarial-review fixes` commits. Fresh panels = spawn reviewer sub-agents with `model: "opus"`, giving each ONLY the diff + a one-line intent (never your reasoning); reviewers are read-only auditors. BLOCK verdicts must be fixed or refuted with a concrete technical counter-argument; cap 3 rounds. Attribution in the PR body names ONLY lenses that actually reported; a stalled lens is never "corroboration"; never write a verdict before the result exists.
7. **Pass-marker** after the final review commit: `mkdir -p ~/.claude/adversarial-review; repo="$(git rev-parse --show-toplevel)"; branch="$(git rev-parse --abbrev-ref HEAD)"; key="$(printf '%s' "${repo}__${branch}" | tr '/ ' '__')"; printf '{"repo":"%s","branch":"%s","head":"%s","verdict":"%s","ts":"%s"}\n' "$repo" "$branch" "$(git rev-parse HEAD)" "CLEAN|CONCERNS" "$(date -u +%FT%TZ)" > ~/.claude/adversarial-review/"$key".pass`. Open the PR (gh CLI, `pr create`) from the worktree root so the hook's key matches, and as its OWN Bash command (the PreToolUse hook gates the whole command it appears in).
8. **Rebase onto the base immediately before push** (`git fetch origin && git rebase <BASE>`), re-run the touched-package tests, then `git push -u origin <BRANCH>`. Migrations: version must exceed main's max at push time.
9. **PR body sections:** Summary / Test plan (commands + results; every `[x]` backed by a run you did) / Manual repro (the matrix) / Screenshots (if UI) / Code review / Adversarial review (rounds, verdicts, findings and their fix commits, lenses that reported) / `Closes PSY-N` (one line per ticket in a family PR). End the body with:
```

<SESSION_URL>
```
10. **Commit hygiene:** per-ticket commits prefixed `PSY-N:`; end every commit message with `Co-Authored-By: <MODEL_NAME> <noreply@anthropic.com>` and `Claude-Session: <SESSION_URL>`. Never `git add -A` (untracked session files exist); add named paths. Do NOT commit `.md` files. Do NOT run `gofmt -w` on `catalog/scene.go`.
11. **Code comments state present-tense invariants only**: never history, ticket narrative, or claims about unmerged sibling work. No em dashes anywhere in code, comments, commits, or the PR body.
12. **Report back** with: PR URL, per-ticket disposition, every gate command + result, the manual-repro matrix, review rounds/verdicts, anything deferred or disclosed, and any follow-up worth a ticket (do NOT file tickets yourself; list them). State every deviation from the brief plainly, including premise corrections.
