# Venue events-page periodic ingest

Keep a venue's whole calendar current (re-run every few weeks). Proven: First Avenue (~330 shows / 7 months).

**Design principle — agent-driven extraction over brittle scrapers.** Render in browser, inspect DOM each run, keep only per-venue *config* (URL, pagination, room→city map). Re-runs are idempotent.

## Invoking

- **Add venue:** `/ingest <env> — add a new venue from its events page: <URL>. Extract all upcoming months, music only, dry-run + both QA scans, pause for OK, write, registry row, register source.`
- **Refresh:** `/ingest <env> — refresh <venue name>'s listings using its registry row.`

Always dry-run + two QA scans + explicit OK before `--confirm`.

## Workflow

1. **Try upstream JSON API first** — grep page/JS for Ticketmaster, SeeTickets, DICE, WordPress REST. Hit JSON directly; cross-check visible card count in browser.
2. **Otherwise render + scrape** — `curl` if server-rendered; browser MCP if JS **or if `curl` is bot-blocked** (HTTP 406/403 from Fastly/varnish TLS-fingerprinting — server-rendered ≠ curl-able, e.g. Pabst Theater Group). Inside the browser session a same-origin `fetch()` reaches any JSON feed the page uses **and** inherits the page's trust — bypassing both the bot-block and CORS (Pabst's `/events/calendar/YYYY/MM` feed; First Avenue's `fetch` loop).
3. **Discover structure once** — card selector, pagination, date format.
4. **Extract all pages** — loop pagination; infer year when month rolls Dec→Jan. Save scratch to workspace path (not `/tmp` for MCP `filePath`); **delete before commit**.
5. **Transform programmatically** — skeleton below; room→city map; music-only filters; don't auto-split `and`/`&` in band names. A source's own genre/category/tag field is a **hint, not a clean filter** — cross-check per title (Pabst `Category` files a jazz fest and a wine tasting under the same codes; LH-ST `data-tags`). Titles carrying no identifiable artist (battle-of-the-bands, a bare festival name) → **skip, don't invent an artist**.
6. **Dry-run + two QA scans:** (a) artist-skip false-positives — pre-create via `POST /admin/artists` (also when the *existing* match is itself a malformed co-bill mashup, e.g. "Blimey and Tommy Oeffling and The B-Team" — pre-create the clean act, flag the mashup for split); (b) headliner sanity — grep for `presents|featuring| with |aftershow|pass$|hosted by`.
7. **Confirm + ingest.** 0-show → site changed, re-inspect.
8. **Register + stamp:**
   ```bash
   bun run src/entry.ts --env <env> search venue "<name>"
   bun run src/entry.ts --env <env> sources register venue <id> "<events_url>"
   bun run src/entry.ts --env <env> sources refresh venue <id>
   ```
   Multi-room org: register each **core** venue entity against the shared URL. **Off-site co-promotions** — a show the org presents at a venue whose own calendar lives elsewhere (Cactus Club→Anodyne, Pabst→Mo's Irish Pub/Fiserv Forum) — create the venue but do **not** register it against this URL.

Manual fix-ups: `PATCH /admin/artists/{id}`, `PUT /shows/{id}`, `POST /admin/artists`, `DELETE /artists/{id}`.

After ingest: [link-enrichment.md](link-enrichment.md) for names-only artists / venue socials.

See [troubleshooting.md](troubleshooting.md) for show dedup, timezone, verify endpoints.

## Transform skeleton + shared rulesets

- **Exclude:** `private event, karaoke, trivia, bingo, sing-along, dance party, drag, burlesque, pride party, wrestling, comedy, zine fest, *moved to*, two day pass, cancelled`. **Keep** `★ Local Show ★`, free residency nights.
- **Clean names** — strip presents/anniversary/afterparty suffixes; drop presenter tokens; comma-split joined acts.
- **Door / music times**, emit `doors_at` / `music_at` on the show item when the source NAMES which time it is. Two ways it can name one: a visible `Doors` / `Show` label, or a field that publishes the event's START (`doors`, `.start-time`, `dates.start.localTime`, `StartDateTime`, `.eventTime`, a Plot `dateTime`'s first half). **Owner decision 2026-09-04: a published event START time IS `music_at`.** PSY-1699's explicit-only rule forbids DERIVING a time, not reading one the source states; a start field states one. Read the START half only, never a range's end, and leave `doors_at` absent unless a doors field exists. A clock with no label AND no field naming its role stays unemitted. Values are the venue-LOCAL wall clock as printed (`"7:30PM"`, `"19:00"`), never an instant and never a date. The parser reads `H:MM AM/PM` and an unambiguous 24-hour `HH:MM` (hour `00` or `13`-`23`); it refuses hours `1`-`12` with no meridiem, because a bare `11:30` names either half of the day. So a 24-hour feed needs its seconds trimmed (`20:00:00` to `20:00`) and only its 1-12 hours re-rendered `H:MM AM/PM`. A source printing a labelled hour with no minutes (`Show: 8 pm`) needs them (`8:00 pm`): that states nothing the source did not. `music_at` is the show's start and anchors `event_date`, EXCEPT below 06:00 venue-local on a date-only listing, where the day it belongs to is not stated and both times are refused. Doors alone is never stored. See the per-source table below.

```js
// node: reads <venue>-raw.json [{date, acts:[...]}] -> /tmp/ph-ingest.json
const VENUE = {name:'', city:'', state:'', address:'', website:''};
const reExclude = /private event|karaoke|trivia|sing-?along|dance party|\bdrag\b|burlesque|pride (party|edition)|wrestling|comedy|zine fest|two day pass|\*moved to/i;
const cleanAct = s => s.replace(/^\*[^*]+\*\s*/,'').replace(/^:\s*/,'')
  .replace(/\s*\((album release|record release|ep release|of [^)]+|[^)]*afterparty|sold out)\)\s*$/ig,'')
  .replace(/\s*\+\s*more\s*$/i,'').replace(/\s+/g,' ').trim();
const isJunk = s => !s || /\bpresents$|^free monday\s*w\/?$|two day pass$/i.test(s.trim());
```
